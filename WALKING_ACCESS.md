# Pedestrian access pilot — October 28, 2026

Open the tracker over HTTP/HTTPS, then choose **Walking access** above the map, **Explore station walking access** in a station profile, or **Explore mapped stop walking access** in an ART/BRT corridor profile.

Choose 5, 10 or 15 minutes and either 1.2 or 0.8 meters/second. Use a connected mapped station entrance, explicitly choose a nearby pedestrian path, or select a path on the walking map. **Avoid mapped stairs** removes mapped steps; it does not certify wheelchair or step-free access. The original station-radius filters and overview totals retain their existing meaning.

Green links are the network walkshed: dark green for 0–5 minutes, medium green for 5–10, and light green for 10–15. The legend shows only bands within the selected time limit. Hover over or tap a green path for the estimated walking-time and walking-distance range from the selected start. Gray links are the other mapped pedestrian paths. The dashed comparison circle shows the maximum straight-line travel distance. No convex hull fills across unmapped crossings or barriers. Path lengths use geodesic distances, with local metric segment projections for point matching. Dijkstra traversal uses shared OpenStreetMap node IDs; visually intersecting lines without a shared node do not connect. Partial final links are clipped to the remaining distance budget, and foot-specific one-way restrictions are respected.

Individual paths split at the 5- and 10-minute thresholds using the shortest network-arrival cost. The calculation handles approaches from both ends and a manually selected start inside a path, so a path's middle can have a different band from its endpoints. Speed and time changes recalculate the bands. Coloring leaves project-access calculations unchanged. Reachable-path GeoJSON includes band colors, estimated minimum/maximum walking times and distances, selected speed, and original source way/segment IDs.

Private/prohibited, conditional-access, construction and proposed links are excluded. Footways, pedestrian ways, paths and steps are included; cycleways/bridleways require explicit pedestrian permission. Street centerlines, including roads carrying a `sidewalk` attribute, are not converted into sidewalks or assumed crossings. Mapped access barriers are respected; unrecorded barriers, hours, signal waits, grades and temporary conditions remain unknown. Time is distance divided by the selected constant speed, without signal-delay or slope penalties.

## Saved coverage and provenance

The release contains 106 lazy-loaded pedestrian snapshots covering all 114 built-in rail-station and ART/BRT planning-stop reference locations. Nearby reference points can share a snapshot. Each snapshot covers a station/stop envelope with a 1,400-meter minimum radius; complete intersecting source ways and their referenced nodes are retained. A coverage warning appears if a user-selected start and walking budget extend beyond this envelope. This is coverage of mapped paths, not a claim that every station has a mapped entrance or every real sidewalk and crossing is recorded.

The original North Avenue, Chamblee and Oakland City snapshots came from bounded OpenStreetMap map API downloads. The other 103 were prepared from [Geofabrik's Georgia OpenStreetMap extract](https://download.geofabrik.de/north-america/us/georgia.html), downloaded October 28, 2026. A two-pass Pyosmium import retains pedestrian ways, original node/way IDs, source tags and mapped subway entrances. Shared IDs determine connections; paths are not joined merely because they cross visually. No source ways had missing referenced nodes in this import.

Source URLs, retrieval times, source timestamps and source-file hashes remain in the snapshots/catalog. Snapshot SHA-256 checksums are recorded in `outputs/walk-data/catalog.json`. Retrieval is not a survey date or field verification. The complete set totals approximately 82.9 MB uncompressed, but only the selected area's snapshot is downloaded. The statewide PBF and Python build dependencies stay in `work/` and must not be published.

Data attribution: **© OpenStreetMap contributors**, [ODbL 1.0](https://www.openstreetmap.org/copyright). The downloadable source snapshots and reachable-path GeoJSON are distributed under that license. No source claims ADA accessibility.

Station/stop selection now loads saved files from the same website instead of making live Overpass requests. A six-entry network cache and shared concurrent requests avoid repeated downloads; switching locations has no artificial waiting period. **Reload walking data** rechecks the published catalog and snapshot files; it does not obtain newer OSM data or change genuine source dates. Missing snapshot files or insufficient mapping produce explicit unavailable/insufficient-coverage states, never a fabricated circle or a zero-access conclusion. Newly added station/stop locations outside saved coverage require a new prepared snapshot.

The [DeKalb County Sidewalk Line Network](https://www.arcgis.com/home/item.html?id=2bb7001523734166962db77d5da37347), owned by DeKalbGISAdmin, supplies the optional official inventory overlay under CC BY 4.0. It was inspected through its published metadata and sample geometries. It provides public sidewalk lines and a planimetric classification, but does not establish the full crossing/entrance topology or survey vintage needed for routing. Therefore it is displayed separately and **never creates or joins graph links**. Queries are spatially bounded and paginated, capped at 5,000 records with an explicit incomplete-overlay warning. The Chamblee browser check loaded 3,246 features. No corresponding verified Atlanta/Fulton/Clayton sidewalk inventory is connected yet.

## Project interpretation

Project pins within 30 m of a reachable path, and within the remaining walking budget including that connector, are **candidates for entrance/access review**. The final connector may cross a barrier or private land and is unverified. Their residential-unit total is a total for these candidates, not a confirmed accessible housing count. Other pins inside the comparison circle remain **access unresolved**; missing mapping does not prove inaccessibility. These totals use all published tracker projects independently of active map filters.

## ART/BRT stops

The same engine supports mapped ART/BRT stop points. Where uploaded routes omit stop records, existing built-in tracker planning references can be used only for an exact route-name match and when the point is within 100 m of the current route geometry. They are prominently labeled **planning reference**, require current stop-plan/boarding verification, and never become automatically approved stops. The pilot does not assume service is operating or available at all hours. Routes without stop data show that limitation. One stop is analyzed at a time; full-route unions of multiple stop walksheds remain future work.

## Validation

`node work/test-walk.cjs` runs 33 geometry, access, import, source-failure, concurrency, provenance, saved-file reload, time-band and export checks. `node work/check-walk-bands.cjs` checks 12 combinations of time/speed across three real station networks, including 25,844 colored features, for valid band bounds and preserved reachable coverage. Browser checks verified the 5/10/15-minute legend, slower-speed redraw, path details, exported band properties, and no horizontal overflow at a 390-pixel phone width. `node work/validate-walk-region.cjs` validates every candidate snapshot's checksum, builds all 106 real networks and confirms saved coverage for all 114 built-in reference locations before installing the candidate catalog. This import had zero uncovered locations and zero empty pedestrian graphs. It does not verify entrances, field conditions or full walking connectivity.

To rebuild saved coverage: run `node work/download-walk-region.cjs`, `node work/prepare-walk-origins.cjs`, then run `work/build-walk-region.py` with Python and the local `work/walk-python` Pyosmium dependency, and finally `node work/validate-walk-region.cjs`. The validator installs the candidate catalog only after all checks pass. Review source dates before publishing. `work/finalize-walk.cjs` belongs to the original three-area installation and is not the regional refresh command.

Real-browser checks covered the North Avenue entrance calculation (5 candidates versus 11 straight-line pins at 10 minutes in the then-current shared project data; 8 versus 16 at 15 minutes), Chamblee's missing entrance and manual path selection, the official county overlay, Campbellton's explicitly labeled Oakland City planning stop, time controls and a 390-pixel phone layout without horizontal overflow. Results can change with project data and the chosen entrance.

The saved-coverage fix was also checked in the browser at Midtown, Airport, Dunwoody, Decatur and the Campbellton Greenbriar planning reference. Mapped entrances produced walksheds at Midtown, Dunwoody and Decatur. Airport loaded its paths and calculated a walkshed after explicit path selection. Greenbriar loaded a sparse mapped network and correctly requested a start rather than inventing a boarding connection. Reload at Midtown preserved the genuine source date, with no browser console errors. All 27 walking checks and 71 existing local-bus/coordination regression checks passed. `node work/check-walk-coverage.cjs` loaded all 114 reference locations through the runtime loader with zero external requests.

## Local preview and publication

Start `node work/serve-walk.cjs`, then open `http://127.0.0.1:4191/`. Network requests and relative JSON files require HTTP/HTTPS; direct `file://` use is not supported by this pilot.

Publish these together: updated `outputs/index.html`, `outputs/trackside-walk-core.js`, `outputs/trackside-walk-data.js`, `outputs/trackside-walk.js`, `outputs/trackside-walk.css`, and the entire `outputs/walk-data/` directory (catalog plus 106 JSON snapshots). Runtime files go at the repository root; `walk-data/` remains a subdirectory. No additional service keys, browser package dependencies or Supabase migrations are required. This task prepares the local feature; it does not publish the new walkshed version to GitHub or modify database records.
